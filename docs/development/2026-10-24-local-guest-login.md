# 2026-10-24 本地入口测试昵称登录修复

## 原因与范围

旧入口在 `F:\fantasy\pokemon-showdown-client`，新入口在开发工作区 `F:\fantasy\release-audit-20261022\client`。两个目录的 `testclient.template.html`、`js/client.js`、`js/storage.js` 在修复前内容完全相同；两份本地服务器配置也都已经启用 `noguestsecurity=true`，绑定 `127.0.0.1:8000`。

旧客户端有本地 `config/testclient-key.js`，新工作区没有。公开的 `Storage.initTestClient()` 实现会在缺少 test key 时，为 `upkeep` 和 `getassertion` 请求显示手工复制验证弹窗。新入口恢复的是这一默认行为，不是游戏存档丢失或浏览器安全设置发生变化。

此次仅检查旧 key 文件的存在和文件元数据，未读取内容，未复制、输出或提交 SID、Cookie 或其他会话凭据。也没有尝试确认旧凭据的账号或有效期。

## 最小业务改动

- 更新器生成的两种快捷方式及自动打开入口均带 `&localguest=1`，保持当前开发工作区和 8000 端口。
- 仅本机 `file://` 页面、精确回环地址和该选项一起满足时使用本地昵称登录。该模式不加载 key 文件，也不安装手工登录代理。
- 客户端直接使用服务器已有的 `/trn 昵称` 流程，不伪造登录断言、不把测试昵称标记成已注册账号。服务器的名称限制、重名检查和受信任账号认证要求仍然生效。
- 仅在服务器接受昵称后将它写入页面本地偏好；刷新和重连恢复同一昵称。连接时的临时 Guest 消息不清除记录，主动退出登录才清除。
- 不自动猜测或更改昵称。第一次使用新页面时输入原测试昵称即可继续原存档，不需要复制验证内容。
- 保留更新工具的原备份、构建和重启步骤，增加本地 guest 配置前置检查和启动后的真实免凭据登录检查；检查账号不读取玩家游戏存档。

原数据库仍是 `F:\fantasy\pokemon-showdown\databases\fantasy-rogue-preview.db`。所有源码修改在两个 `codex/fantasy-rogue` 工作区完成。没有修改正式分支、旧入口配置或腾讯云。
