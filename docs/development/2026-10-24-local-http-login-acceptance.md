# 2026-10-24 Windows 本地 HTTP 入口与普通昵称验收

本记录取代此前 file 入口方案的完成结论。此前仅验证单元测试和协议模拟，用户录屏证明实际 Edge 仍有手动验证；本次补充实际浏览器操作，不将协议模拟当作浏览器验收。

## 根因

1. 旧客户端目录存在本地 `config/testclient-key.js`，新工作区没有。只检查文件存在与元数据，未读取、复制、输出或提交凭据。缺少 key 时，原生 testclient 会进入手工登录代理。此前 file 入口又依赖查询参数；录屏中实际打开的地址未带参数，无法激活本地昵称分支。
2. 旧预览器在读取 Config 前设置 `FANTASY_AI_LOCAL=1`，统一更新器最初遗漏了这一步。只有 `noguestsecurity` 能使普通昵称登录，不能开启 Rogue 的本地开发权限；生产白名单于是继续生效。
3. 切换 HTTP 后，用户截图的“连接中”并非仍在等待登录：实际 Edge 控制台显示公开配置缺少 `whitelist` 和 `customcolors`，导致链接处理和用户名颜色初始化异常。已补齐必要公开配置与回归检查。
4. 实际刷新测试又发现昵称恢复失败。偏好已正确保存，客户端也发出 `/trn`，但启动界面的批量查询占满聊天节流队列，服务端丢弃自动登录命令。仅在已验证的 Windows 回环开发进程中启用 `nothrottle`；启动健康检查加入八条查询后再登录，防止遗漏重现。

## 当前实现和隔离

- 入口固定为 `http://localhost:8080/testclient.html#fantasyrogue`，不依赖查询参数。HTTP 客户端和 8000 战斗服务来自同一更新记录，绑定 `127.0.0.1`，未知 8080 端口占用会使更新中止。
- 动态生成纯公开的开发配置；不读取 test key，不代理正式账号登录。HTTP 只提供构建资源并检查 Host、Origin、真实路径，拒绝 key、数据库、源码、source map 和目录越界。
- 当前开发工作区仍是 `F:\fantasy\release-audit-20261022\server` 与 `client`，二者均为 `codex/fantasy-rogue` 的实际 Git worktree。构建使用最新工作区内容，未复制旧源码或切换分支。
- `server/fantasy-rogue/access.ts` 未修改。生产仍要求注册身份和内测名单（或生产原本明确配置的公开权限）；仅服务端开发标志加回环监听能启用本地预览。客户端伪造参数不会改变生产权限。
- 原更新器的配置／SQLite 备份、未提交内容指纹、构建失败保护和进程身份核对继续保留。原数据库路径、8000 端口和玩家数据不变。
