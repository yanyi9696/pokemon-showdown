# Fantasy Rogue 新版存档的应急续玩与发布边界

## 结论

**不得将写入过本轮新存档的数据库交回生产旧版 `91b031b7a4098d2186aacf9b1ccf909b0d2fa7b6` 运行。**
数据库表结构兼容不等于游戏状态兼容。旧代码不能处理 `mainlinechoice`，也不能正确解释
`boostRuleVersion = 2` 的百分比成长。本方案是保留新版数据语义的**前向修复/应急续玩**，
不是旧版完整回退补丁，更不能保证绕开新版引擎本身的任意缺陷。

本轮发布保留新主线、挑战、奖励、成长、历史记录的完整实现；服务端可配置
`Config.fantasyrogue.continueOnly = true`。此模式只拒绝 `start`、`newstory` 新开旅程，
允许已有冒险、剧情回应、战斗、奖励及收藏操作继续执行。关闭开关即可恢复新开旅程。
开关只来自管理员服务端配置，不读取客户端参数。默认关闭；不改动生产账号权限。
已经成功的新开请求在重试时仍返回原存档，不因开关变化重复创建或错误报失败。

## 不能交给旧版处理的状态

- 未读完的主线、分支选择、老人互动、身份揭露与待触发的真正结局，以及剧情驱动的档位解锁。
- 百分比局外成长的进行中冒险、通关卡与历史快照；无此标记的旧冒险继续沿用原加点语义。
- 新挑战区域的邀请、退出后选择、待领取奖励、训练增幅及同行邀请。
- 本轮新增或修改的祝福、属性转、伙伴培养、战斗规则及其待处理选择。
- 物种首通台账、跨局成长、奖励防重记录、新版历史展示字段等旧版不认识的语义。
- 任意高于本版本数据契约的未来存档。新增 `saveVersion` 是运行时保护标记，旧代码不会
  自动遵守它；因此该标记**不能使旧二进制变安全**。未标记的旧存档仍允许升级。

已有账号在下一次有效保存时写入 `saveVersion: 2`，不改变 SQL schema/user_version。
当前代码在读取及事务写入前拒绝未知存档版本、未知成长规则，报错而不重置玩家数据。
新数据契约变化必须更新版本及兼容验证，不能只改这个数字来宣称兼容。

## 部署人员的隔离验证

以下命令仅用于**已经验证完整性的生产一致性备份的可丢弃副本**。不要对生产路径、原始备份运行。
SQLite 在 WAL 模式下必须使用在线 backup API 或停写后的完整一致性备份，不能单独复制活动 `.db`。
为每次检查创建独立目录；保留原始备份及哈希。不要将任何数据库放进 Git。

1. 在独立源码目录检出本报告指定的服务端 SHA，配套客户端也必须使用本报告 SHA。
   正常安装依赖、运行 `node build --decl`；不能把旧 dist 拼接到新版本。
2. 使用既有 `tools/validate-fantasy-rogue-database.js` 执行隔离 schema 升级验证。
   输入已核验的一致性备份及其 SHA-256；输出目录必须尚不存在。工具先核对哈希，再创建
   `validation-copy.db`，只在该副本上初始化，并再次验证输入备份未改变：

   ```sh
   node tools/validate-fantasy-rogue-database.js /isolated/input/fantasy-rogue.db <verified-sha256> /isolated/validation-new
   ```

   不在原备份或生产路径上初始化；任一步失败都停止后续流程。
3. 对升级后的副本执行只读预检（参数路径由部署人员填入）：

   ```sh
   node tools/check-fantasy-rogue-compatibility.js --database /isolated/validation-new/validation-copy.db --target /isolated/new-server
   ```

   返回 0：数据契约、现有表结构和 SQLite 完整性检查通过。返回 2：停止，保留错误与备份，
   不自动修复、降级或清空数据。输出只有表计数和检查结论，没有账号或存档内容。
   此工具不会初始化表、修改 JSON、执行迁移或写入业务数据；`finally` 释放连接。
   未带兼容契约的旧源码目录会被拒绝，即使数据库能够被 SQLite 正常打开。
4. 运行回归验证：

   ```sh
   node node_modules/mocha/bin/mocha.js --no-config test/main.js test/server/fantasy-rogue-save-compatibility.js test/server/fantasy-rogue-store-schema.js test/server/fantasy-rogue-mainline.js test/server/fantasy-rogue-optional-challenges.js test/server/fantasy-rogue-history-snapshots.js --timeout 30000 --reporter spec --exit
   ```

5. 部署方在第二份可丢弃副本上，开启 `continueOnly`，核对实际备份中的主线选择、挑战结算、
   旧/新成长冒险、通关卡、奖励及历史记录。只读预检是必要条件，**不能替代业务续玩验证**。
   对比升级前后账号数、历史行数与逐账号关键字段；检查未操作的存档不丢失数据。
   本地开发只测试合成数据，不代表已经验证生产备份。

## 实际故障时的前向恢复步骤（须由部署方另行授权执行）

1. 先停止新的入口/进入维护，记录异常请求和失败状态，避免玩家重复操作扩大影响。
2. 保留故障时最新的数据库一致性备份、WAL、配置、日志、源码 SHA 及完整构建产物。
   这些包含上线后的玩家进度；不要用上线前备份替换它们。
3. 在隔离副本重现故障。修复候选必须从本轮兼容代码派生，保留以上数据语义；只撤销有问题的
   非数据功能或前向修复具体逻辑。若无法验证某状态，保持维护，不允许旧代码猜测处理。
4. 完成上述预检及续玩验证后，使用匹配的新服务端/客户端完整构建，配置
   `fantasyrogue.continueOnly = true`，按部署流程切换代码，继续使用**当前数据库**。
5. 验证登录、既有冒险/主线/奖励、防重及历史读取；观察错误后再恢复新开旅程。

重启无法恢复进程内尚未落盘的对战。现有管理器会检查对战房间是否仍存在，并按已有断线恢复
流程处理；不能承诺从丢失进程的同一回合原地续战，也不能将数据库回档当作解决办法。
已经落盘的对战结算通过 encounter ID、请求 ID、revision 和 SQLite 事务防止重复发放。

## 事务与验证范围

账号 JSON、请求回执、通关卡和历史写入保留在同一个 `BEGIN IMMEDIATE` 事务中。
此次没有删除表、改列、清空历史或更换数据库，也没有给兼容检查添加任何自动数据修复。
合成回归覆盖：旧加点/新百分比成长分离、重复迁移、新主线中途关闭重开、分支续玩与领奖、
同一请求重试、过期选择拒绝、挑战奖励续领、最后一步 SQL 失败后的全事务回滚及再次提交、
新局维护限制、未知版本拒绝、只读预检和异常时连接释放。

完整 ESLint 仍有生产基线已存在的失败；本轮按生产基线逐诊断比较并清除新增项，不关闭规则。
默认 `full-test` / master CI 的零警告 ESLint 门禁仍会被历史债务阻断，不能报告完整 CI 已通过。
测试通过仅指单独执行的 TypeScript、构建和回归命令，详见交付报告。
